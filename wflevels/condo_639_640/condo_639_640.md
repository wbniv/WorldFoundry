# condo_639_640 — 205/639 + 205/640 air‑con walkthrough

A doll‑house walkthrough of the two condo units and their split‑system installation study,
converted from the Blender study `~/docs/aircon/units-639-640.blend` (generated by
`~/scripts/aircon-blender.py`; rebuild the model with `cd ~ && task aircon-blender`).
The model is an outline‑and‑partitions study, not a survey: interior walls follow the doc's
schematic rooms; front‑door positions and the 2.4 m drop ceiling are assumptions.

Plan and mapping decisions: [docs/plans/2026-09-19-condo-639-640-level.md](../../docs/plans/2026-09-19-condo-639-640-level.md).

## Controls (doom‑stick, `Turn Rate = 0`)

| Input | Effect |
|---|---|
| ▲ / ▼ | walk +Y (toward the back / balconies) / −Y (toward the front doors) |
| ◀ / ▶ | strafe −X / +X in the floor plan (independent of camera orbit) |
| A (Space) | small hop |
| B (`2`) | operate the project-room glass-door switch while standing beside it |
| C (`3`) | teleport between 639 and 640, returning to the last position visited in each |
| Hold D (`4`) + ◀ / ▶ | orbit left / right around the player |
| Hold D (`4`) + ▲ / ▼ | raise / lower the inspection angle |
| E / F (`5` / `6`) | zoom closer / farther |
| D+A (`4` + `1` or Space) | reset view and restore automatic window/patio shots |
| D+B+▲ / ▼ | zoom fallback for controllers without shoulder mappings |


Both remembered positions start just inside their respective front doors and
update while walking indoors. Holding C switches once; release it before the next
switch. The master suite and the room joined to 639 belong to 639 for this control.
Walking into the outside corridor preserves the last indoor position. Teleporting
stops momentum and moves the camera to the destination. Positions reset when the
level reloads; the automatic tour keeps its waypoint controls.

The glass itself is always solid: when open, only the clear two-thirds of the threshold
is passable; the gathered one-third stack still blocks. When closed, all three panel
thirds and their seams block the full threshold.

Spawn: just inside 639's front door at `(4.66, −14.5, 0.3)` (relative to the unit floor), facing +Y. Walking pace ≈1.5 m/s
(`Running Acceleration` 40; ground speed ≈ accel/26 — `CONDO_ACCEL=` overrides).
Camera `cs_dollhouse`: relative offset `(0, −3.5, 9)` from the player, looking at the chest.

## Camera inspection and touch profile

The camera controls are implemented in [camera_controls.fth](camera_controls.fth).
Runtime input, state, orbit maths, limits, reset and touch-mode labels are all
Forth. There are no camera-specific engine changes. The subsequent shared
[Forth comment fix](../../docs/forth-script-loading.md) removes the former
packaging workaround, so the camera source is passed through unchanged. Holding 4 stops horizontal motion
and consumes arrows/jump. Manual view settings persist until reset/reload and
survive apartment switching. Orbit does not change the floor-plan walking axes.

Orbit speed is 60°/s, tilt is 30°/s and zoom is 3 m/s, with a 50 ms timestep cap.
The elevated inspection view uses 35–80° elevation and 4–12 m distance, further
limited by floor clearance and room height. These coupled limits avoid the
existing shell/bungee collision response; this is not unrestricted first-person
or free-fly navigation. Reset restores the exact authored camera offset.

Build the ordinary keyboard/controller version with `task condo-level`. Build the
separate two-button version with `task condo-touch`; load
`wflevels/condo_639_640_touch-standalone.iff` with the same condo VRAM arguments.
The touch task selects `CONDO_CAMERA_PROFILE=touch` in level packaging.

| Touch input | Action |
|---|---|
| Tap A | cycle Walk → Look → Zoom → Walk |
| D-pad in Walk | walk |
| D-pad in Look | orbit left/right; tilt up/down |
| D-pad in Zoom | up closer; down farther |
| Tap B | nearby project-room door |
| Hold B for 0.6 s | reset camera and return to Walk |
| A+B together | switch apartment once, retaining mode/view |

A/B taps act on release; a chord cancels both pending taps until both buttons
release. A changes mode instead of jumping in the touch profile. A floating
level-mesh label shows the current mode and next A action. Desktop uses the
visual control guide; the proposed screen overlay was not added to the engine.

Android currently exposes the required D-pad and A/B touch regions. The profile
passes injected-input tests, including staggered releases. Actual phone/tablet
hitboxes, multi-touch cancellation and hardware gamepad mapping need device
validation. iPhone/iPad host bindings remain unverified. Right-stick look and
pinch/drag gestures are not exposed by the inspected input ports.

[Keyboard, joystick and phone/tablet diagrams](../../docs/plans/2026-09-25-condo-camera-controls/mockups.html)
· [Actual runtime captures](../../docs/plans/2026-09-25-condo-camera-controls/runtime.html)

## Site — where the units really are

The units are on the **6th floor** of a condo at
[34 Soi Sathu Pradit, Bang Phong Phang, Yan Nawa, Bangkok 10120](https://maps.app.goo.gl/CTkxPDsuX7umeZwX8)
(13.6935894 N, 100.5334137 E), back (balconies) facing straight **west**. `site_constants.py`
holds the pin, the compass mapping and the elevation; `make_site_textures.py` turns a committed
OpenStreetMap extract (`site-osm.json`, ODbL; `task condo-osm-fetch` refreshes it) into the two
textures (`task condo-textures`, offline and byte‑stable).

| Compass | Level axis | What's there |
|---|---|---|
| West | +Y | balconies, the Chao Phraya ≈ 1.6 km out |
| East | −Y | front doors, corridor, Sathu Pradit Road 11 m from the pin |
| North | +X | unit 639 is north of 640 |
| South | −X | |

Elevation: `UNIT_Z = (6 − 1) × (3.0 m clear + 0.15 m slab) = 15.75 m` — everything is authored
with the unit floor at z = 0 and lifted in one pass at the end of the script, so the tour path,
`darken_floors` and the slab outline never see the offset. The map pin geocodes to the Soi 34 /
Sathu Pradit Road corner (a road in OSM, not a footprint): `SITE_OFFSET_EN` in
`site_constants.py` slides the level origin east/north once the real building is identified.

**The surroundings** (plan: [condo-site-surroundings](../../docs/plans/2026-09-19-condo-site-surroundings.md)):
every OSM footprint within 150 m is extruded into one `site-buildings` mesh (heights by
building type — nothing near the pin is tagged), a `site-podium` box carries floors 1–5 under
the units, the sky panorama holds the 642 towers ≥ 40 m within 8 km and the four cable‑stayed
bridges (Rama IX, Bhumibol 1 and 2, Kanchanaphisek — pylon heights from a table, OSM has none).
[`site-catalog.md`](site-catalog.md) (generated) lists what is there and which window sees it.
Winding: author for Blender — `recalc_face_normals` for exterior geometry, `reverse_faces` only
for the dome the player stands inside; the exporter adapts Blender's hand to the engine's
(`(v2−v0)×(v1−v0)`) since [2026‑09‑19](../../docs/plans/2026-09-19-exporter-face-hand.md).
Prisms have no bottom face and the podium is inset 5 cm from every surface it touches —
coincident faces at the ground flickered.

Textures ride the PERM atlas at 1024² (`textile.flags`), which needs the `--vram-*` flags
`run-condo` and the tour recorder pass. `CONDO_CAM=x,y,z` / `CONDO_LOOK=x,y,z` override the
doll‑house camera/aim offsets for screenshots. Plan:
[docs/plans/2026-09-19-condo-site-skybox.md](../../docs/plans/2026-09-19-condo-site-skybox.md).

## Window cameras — step onto 639's patio or up to 640's master window and you're looking at Bangkok

The doll‑house shot pitches 69° down, so the sky is never in its frame. `ActBoxOR` zones
switch shots: `zone-interior` (both units + corridor) → `cs_dollhouse`; `zone-balcony`
(the `639-patio` + `639-patio-recessed` outlines) → `cs_balcony`; `zone-master` (the 1.6 m
strip along the master bedroom's curved south glass, x ≤ −6.3) → `cs_master`. The balcony
zone begins at y = −1.55, after the player has cleared the glass-door plane, so the shot does
not cut mid-doorway. Both 52° POV shots are `Relative` offsets from the player at eye height —
(0, 1.5, 1.7) past the pony wall, (−1.8, 0, 1.7) past the glass — in free air outside the
unit's bbox. A one-second blend enters each shot. While you stand there a scripted look
target (`BalconyLook` / `MasterLook`, platforms like the moon's `launch_tracker`) pans the
skybox over 5 s with smoothstep easing. Both target paths stay distant and near the horizon:
the balcony sweeps `(-6,15,0.6) → (8,15,2.0)`, while the window sweeps
`(-18,-11,0.6) → (-18,2,2.0)` through KCC and the bridge skyline. Timing comes from mailboxes 97 / 96
(the Director records the level time you stepped in, zeroes it when you leave); walk back
and the doll‑house returns. Plans: [site skybox](../../docs/plans/2026-09-19-condo-site-skybox.md),
[master window](../../docs/plans/2026-09-19-condo-master-window-pov.md).

Facts this depended on (the CamShot docs are being corrected — see TODO):

- `movecam.cc SetCameraParametersFromShot`: `Relative` → position = (camshot − Follow) +
  Track Object; `Absolute` → the camshot's own point; direction = Target − camshot, world
  space. `Fixed` only means "don't add the tracked object's heading".
- The camera is a physics body: whenever its bbox overlaps any actor with `Mass > 0`
  (`Actor::CanCollide`) it stops seeking Z and **climbs** (`BungeeCameraHandler` ClimbRate) —
  so a POV camera inside a room sails upward, and the sky dome must have `Mass 0` or its
  world‑sized bbox counts as a permanent collision.
- In bungee mode (`FLAG … 1` in the standalone wrapper) `INDEXOF_CAMSHOT` is re‑read every
  tick and never cleared: the last index written wins; an `ActBoxOR` writes its mailbox every
  tick the player overlaps it and never clears it, so the Director forwards and zeroes.

## Not mapped

- **The building's real footprint** — the podium is the units' own footprint; the real block is
  probably the L‑shaped one 65 m north‑west of the pin (`SITE_OFFSET_EN` pins it).
- **Glass transparency** — `MATL` has no alpha; panes are opaque light blue.
- **`unit-640-drop-ceiling`** — hidden in the source and it would hide 640's interior from
  the overhead camera.
- **`640-midea-option-B-over-door`** — rejected alternative, hidden collection, never appended.
- **Consumer‑unit material** — none in the source; given a light‑grey flat colour.
- **Tube end caps** — bevelled curves export as open tubes (invisible at 4–6 cm radius).
- One sub‑threshold triangle (a bevel corner on `639-daikin-power`) is dropped so the engine's
  face‑normal assert doesn't fire; see the troubleshooting doc.
