# condo_639_640 — 205/639 + 205/640 air‑con walkthrough

A doll‑house walkthrough of the two condo units and the planned split‑system installation,
converted from the Blender study `~/docs/aircon/units-639-640.blend` (generated by
`~/scripts/aircon-blender.py`; rebuild the model with `cd ~ && task aircon-blender`).
The model is an outline‑and‑partitions study, not a survey: interior walls follow the doc's
schematic rooms; front‑door positions and the 2.4 m drop ceiling are assumptions.

Plan and mapping decisions: [docs/plans/2026-09-19-condo-639-640-level.md](../../docs/plans/2026-09-19-condo-639-640-level.md).

## Build & run

```bash
task condo-level          # Blender export (needs the wf_blender add-on) + build-level
task run-condo            # WF_RECORD=1 / WF_FULLSCREEN=1 as usual
CONDO_BLEND=/other/units-639-640.blend task condo-level   # alternate source model
CONDO_SPAWN=2.0,-11.0,0.3 blender --background --python wflevels/condo_639_640/blender_create_condo.py
                          # spawn override for screenshots (639 kitchen); then task build-level -- condo_639_640
```

Re‑running `task condo-level` is a no‑op until the `.blend`, the script or the standalone
wrapper changes.

`task video-condo-639` → [`tour-639.mp4`](tour-639.mp4) (30 s, 640 × 480, burnt‑in room captions;
`tour-639.srt` alongside). The tour build `wflevels/condo_639_640_tour` is the same level with the
player's Forth replaced by a waypoint servo compiled from [`tour-639.path.json`](tour-639.path.json)
(`task tour-condo-639`); `tests/record_condo_639_tour.py` records it and post‑processes with ffmpeg.
Route: front door → kitchen → bath‑S → project room → guest bedroom → back bath → recessed patio →
patio → party‑wall connector → 640 room‑2.9×3.3 → master bedroom → closet → master bath.
Plan: [docs/plans/2026-09-19-condo-639-tour-video.md](../../docs/plans/2026-09-19-condo-639-tour-video.md).

## Controls (doom‑stick, `Turn Rate = 0`)

| Input | Effect |
|---|---|
| ▲ / ▼ | walk +Y (toward the back / balconies) / −Y (toward the front doors) |
| ◀ / ▶ | strafe −X / +X (screen left / right) |
| A (Space) | small hop |

Spawn: on the ground outside 639's front door at `(4.66, −17.0, 0.3)`, facing +Y. Walking pace ≈1.5 m/s
(`Running Acceleration` 40; ground speed ≈ accel/26 — `CONDO_ACCEL=` overrides).
Camera `cs_dollhouse`: relative offset `(0, −3.5, 9)` from the player, looking at the chest.

## What maps to what

| Blender | WF actor | Notes |
|---|---|---|
| `unit-639`, `unit-640` | `statplat` mesh, same name | shell = floor slab + exterior walls, openings cut in; Jolt trimesh |
| `<unit>-<name>-wall`, `…-jambN`, `…-door-header`, `….001` | `statplat` mesh, same name | rotation + scale baked into the mesh |
| `640-window-0`, `639-window-1`, `640-curve-window-1..6` | `statplat` mesh, same name | opaque light‑blue glass, thickened 0.02 → 0.10 m |
| `*-indoor`, `*-outdoor`, `*-consumer-unit`, `640-midea-*-A-closet-wall` | `statplat` mesh, same name | props |
| `*-power`, `*-lineset`, `*-drain` (curves) | `statplat` mesh, same name | bevel → tube mesh; red / copper / light blue |
| room outlines (display WIRE: `639-kitchen`, `640-bath`, …) | `target`, same name | bbox = room; invisible locator, no collision |
| — | `site-ground` | 28 × 28 m slab flush at z=0 with a hole under each shell (prism boolean), so floors meet edge-to-edge |
| — | `Player`, `CamTarget`, `LookAt`, `cs_dollhouse`, `Camera`, `Sun`, `AmbientLight`, `Matte`, `Level`, `Director` | infrastructure |
| both units | `room_condo` | the **single** WF room; condo rooms are the `target`s above |

Mesh files are `<slug>.iff` (lowercase, non‑alnum → `_`, ≤ 30 chars — long names are cut to
21 chars + a 4‑hex CRC), while the actor `NAME` in the `.lev` keeps the Blender name verbatim.

## Files

`blender_create_condo.py` (conversion), `condo_639_640.blend` (assembled WF scene, `room_condo` hidden), `condo_639_640.lev` + `*.iff` meshes (export), `condo_639_640-standalone.iff.txt` (L4 wrapper), `tests/walk_condo.py` (bridge-driven collision check).

## Not mapped

- **Glass transparency** — `MATL` has no alpha; panes are opaque light blue.
- **`unit-640-drop-ceiling`** — hidden in the source and it would hide 640's interior from
  the overhead camera.
- **`640-midea-option-B-over-door`** — rejected alternative, hidden collection, never appended.
- **Consumer‑unit material** — none in the source; given a light‑grey flat colour.
- **Tube end caps** — bevelled curves export as open tubes (invisible at 4–6 cm radius).
- One sub‑threshold triangle (a bevel corner on `639-daikin-power`) is dropped so the engine's
  face‑normal assert doesn't fire; see the troubleshooting doc.
