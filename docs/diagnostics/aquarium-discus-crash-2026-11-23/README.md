# Discus desktop load failure

Will reported a crash with the initial Pixel APK (`8451e47513dc03e6b5e20005d1408b295f4c6d826dce71c833252b8eaf7e2be5`); its phone crash trace has not been captured. An older desktop engine aborts on the Discus settings object. An earlier claim that the APK lacked the settings type was based on a case-sensitive string check and is unproven: a case-insensitive check finds the name in the library.

With the matching engine from the Discus worktree, the original level separately exhausted its 3,000,000-byte room heap while loading a 359,448-byte allocation, with 153,776 bytes remaining. The corrected wrapper uses 8,000,000 bytes and one room slot. It is generated by `wflevels/aquarium/blender_create_aquarium.py` in the Discus worktree. The matching cooked playable and screensaver levels then loaded and ran in the desktop container. The scripted playable run moved the player 5.819 units right and all nine residents; the screensaver run moved the automatic player 0.661 units and all nine residents. The JSON files here record the actor positions and timing; the image is from the screensaver run.

The matching two-ABI release APK has SHA-256 `ff8e05416ceb1e71591f988c3db29769fded9c0e7608752538def899ad`. Install receipts verify that hash on cast1 (J‑3ddb7c24de89), cast2 (J‑f41d2be63893), and Pixel (J‑bc7beb15133e). Cast2 then needed transport recovery. Cast1 check J‑feda8ba91131 and Pixel check J‑7938126170ec selected Discus and captured the tank; the Pixel check verified 24 touch edges. See [cast1](cast1-discus.png), [Pixel](pixel-discus.png), and [Pixel touch evidence](pixel-touch-evidence.json). Device screensaver and longer performance checks remain open. The original phone crash trace remains unconfirmed.
