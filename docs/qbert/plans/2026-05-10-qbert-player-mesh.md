# Real Q✱bert player model

**Status:** Done 2026-05-10. Originally landed with snout pointing +Y (wrong — see "Coordinate system update" note below); corrected later the same day to author the mesh in WF actor convention (snout = +X = engine forward).

## Coordinate system update (2026-05-10, post-rotation work)

WF's actor convention is **+X forward**, +Y left, +Z up (see [project_wf_axis_convention](../../../.claude/projects/-home-will-WorldFoundry/memory/project_wf_axis_convention.md)). The original draft of this plan authored the mesh with the snout on **+Y** because the camera at `(0, -22, 23)` looks +Y, so "+Y in mesh space = toward the viewer." Visually correct for the rest pose, but **wrong** for the engine — when the [Phase 1 hop-rotation feature](2026-05-10-qbert-hop-facing-rotation.md) shipped, it computed yaw deltas in engine-+X-forward terms, so the visible mesh appeared ~180° off from the script's intended facing.

The corrected wiring (in [blender_create_qbert.py](../../wflevels/qbert_practice/blender_create_qbert.py)):

- Mesh snout / eyes / feet point **+X** in mesh-local space.
- Legs straddle the **±Y** axis (was ±X).
- The `player` object's `rotation_euler.z = -π/2` is set at level placement so the engine's +X forward maps to world `-Y` — snout points toward the camera at rest.

This way both the engine's "forward" and the mesh's visible "forward" are the actor-local +X axis. Future rotation/animation code stays consistent.

## Context

The qbert_practice level currently uses a placeholder two-box mesh for the player, generated by a hand-written binary writer (`gen_player.py`) that bypasses the Blender export pipeline. The mesh is just two stacked AABBs in orange/peach — it doesn't read as Q✱bert at all, and it lives outside the proper asset pipeline.

The fix: author a real 3D Q✱bert in Blender using primitives (sphere body, smaller sphere head, conical snout, two cylinder legs), with proper materials, and let the standard `wf_blender/export_level.py` pipeline produce the binary `.iff`. Drop the `gen_player.py` workaround entirely.

The exporter ([wftools/wf_blender/export_level.py](../../wftools/wf_blender/export_level.py) `_write_mesh_iff`, ~lines 422–537) already supports unlimited materials per mesh, per-face `material_index` → MATL slot mapping, and Principled BSDF Base Color → RGB conversion. The cube system (3 materials × 48 meshes) proves the multi-material path works.

Q✱bert silhouette (3D interpretation — only the 2D arcade sprite is copyrighted): orange spherical body, smaller orange head on top, prominent tubular/conical snout, two stubby orange cylinder legs, no arms. Peach/skin accent inside the snout. Total height matches existing ~2-unit footprint so camera framing and hop physics stay valid.

## Approach

Build the player mesh procedurally in [blender_create_qbert.py](../../wflevels/qbert_practice/blender_create_qbert.py) using `bpy.ops.mesh.primitive_*` operations, joined into a single mesh object with multiple material slots. Let the existing exporter handle the binary write. Do **not** modify any binary `.iff` or `.lev` files directly.

### Mesh construction (in `_build_qbert_player_mesh`)

Single mesh object named `Player`, joined from primitives, in object local space (level placement unchanged):

1. **Body** — UV sphere, radius 0.55, segments=16, rings=12, centered z=0.55. Material `qbert_orange`.
2. **Head** — UV sphere, radius 0.40, centered z=1.25. Material `qbert_orange`.
3. **Snout** — Cone, r1=0.18, r2=0.10, depth=0.45, rotated 90° about Y (points **+X** = engine forward), origin (0.40, 0, 1.20). Material `qbert_snout` (peach 0xFFAA66).
4. **Legs** — Two cylinders, radius 0.13, depth 0.30, at (0, ±0.22, 0.15) — straddling the ±Y axis. Material `qbert_orange`.
5. **Feet** — Two flattened spheres, radius 0.20, scaled (1.2, 1.0, 0.4) so they elongate along forward (+X), at (0.05, ±0.22, 0.04). Material `qbert_feet` (darker orange 0xCC5500) so they read against the cube tops.
6. **Eyes** — two small white spheres on the +X (front) of the head at (0.30, ±0.14, 1.40), material `qbert_eye_white`.

Then select all → `bpy.ops.object.join()` → set origin to `(0, 0, 0)` (feet on ground) → apply rotation/scale → name `Player`.

### Materials

`bpy.data.materials.new()`, `use_nodes=True`, set Principled BSDF `Base Color` `default_value`:

- `qbert_orange`: (1.00, 0.53, 0.00, 1) — 0xFF8800
- `qbert_snout`: (1.00, 0.67, 0.40, 1) — 0xFFAA66
- `qbert_feet`: (0.80, 0.33, 0.00, 1) — 0xCC5500
- `qbert_eye_white`: (1.00, 1.00, 1.00, 1) — 0xFFFFFF

Assign per-face by setting the active material slot on each primitive object *before* the join — Blender remaps polygon `material_index` correctly during join.
