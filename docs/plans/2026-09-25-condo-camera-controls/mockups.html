Keyboard · existing key mappings

Number-row keys are confirmed in the Linux and macOS mappings. Camera chords consume movement/jump before locomotion sees them.

Joystick / gamepad · Xbox-style labels

Y + directions: orbit/tilt · X: apartment · B: door · Y+A: reset. Y+B+↑/↓: zoom fallback. * Left stick and shoulders depend on host mappings; macOS needs the zoom fallback.

Phone / tablet · two-button touch profile

Tap A to choose what the D-pad does:

Walk: move player
Look: orbit left/right, tilt up/down
Zoom: up closer, down farther

Tap B: nearby door
Hold B, 0.6 s: reset + Walk mode
A+B: teleport once

Taps fire on release. Chords cancel taps. A changes modes instead of jumping in this profile.

Existing Android input: D-pad + A/B touch regions. Labels and mode strip above are proposed, not native UI changes. Select the touch profile in the level build. No pinch, drag-look or added touch buttons. Test fixed-pixel hitboxes on real phones/tablets. iPhone/iPad host bindings remain unverified.

Orbit around a stable point

Top-view concept. The camera’s actual room clearance must be validated. This drawing does not imply unrestricted movement through walls.

Tilt and zoom to reveal detail

Zoom changes camera distance. Elevated bounds keep the view away from the shell collision response and vertical look-at singularities.
