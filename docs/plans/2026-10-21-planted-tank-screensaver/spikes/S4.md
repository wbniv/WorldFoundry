# Spike S4: building a plants-only variant

Read from source on 2026‑10‑21 (branch `2026-new-level`). Nothing was built or run.

## Verdict

**RECOMMENDED: a generator flag. Do not strip text.** No switch exists today: `KIND=='plants'` always builds the urchin, the goby and 12 seahorses. But `generate.py` assigns every actor index and writes every baked index into the Forth scripts in one pass, so leaving the animals out *there* renumbers everything consistently for free. A text strip would have to renumber 13 surviving actors and regenerate both scripts, which means re-implementing `generate.py` in the builder. A wrong index fails silently, and it can write urchin poses onto plant chunks.

**New finding that Phase 1 must fix.** The existing screensaver variant has **no `RPRP` catalog**. `build-aquarium-screensaver-levels.py:62-87` never calls `build-object-properties.py`. On disk, `aquarium_plants-standalone.iff` holds 2 `RPRP` tags and `PlantedTankSettings`, while `aquarium_plants_screensaver-standalone.iff` and `aquarium-screensaver-cd.iff` hold 0 of each. Without a catalog, `planted::enter()` logs `settings-source=legacy-defaults` (`plant_settings.h:28-40`), `property@` fails, and **the Phase 2c launch-override table would have no `PlantedTankSettings` object to override**. `Hold seconds` would not exist either. The variant must get its catalog attached the way `aquarium_plants/build.sh:15-26` does.

### Exact steps (Phase 1)

It holds `config.py` (the plants config plus `ANIMALS=False`, `WIDE_CAMERA=(0,-8.25,2.5)` and the fog distances), `build.sh` (a copy of `aquarium_plants/build.sh` with the level name changed), its own `settings.oas`, and its own `settings-bindings.json`. Its `textile.flags` drops `PERMPAGEX/Y=1024`.

### Risks

- **Editing a shared generator.** The default `ANIMALS=True` must leave `aquarium_plants.lev` byte-identical. Guard this by rebuilding it in the container and comparing it with `git diff --exit-code`.
- **The Player stays mandatory.** `Level::reset()` asserts on it (see Q3). If someone "simplifies" it away later, a release build crashes when it calls `GetObjectIndex(NULL)`.
- **`plant_settings_catalog.py` cannot cook this variant.** `HERE` is hard-wired to `aquarium_plants` (`:13`), and `validate()` always fills `seahorses` and `greeting` (`:21`), which raises `KeyError` on `bindings['fields']['Seahorses']` (`:79`) when the bindings drop those fields. Cook the variant only with `build-object-properties.py`.
- **A desktop tap** still toggles mailbox 625 (`game.cc:677`). With `tk-camera-tick` kept, it shows a close view of the empty spawn point. Use a fixed wide CAMSHOT if that matters. The Dream takes no input.
- **The level runs in the Blender container** (`scripts/level-build.sh`), the same as the canonical tank, so it adds the same container dependency.

## Evidence

### Q1: where the animals are defined, and whether a switch exists

`aquarium_plants/config.py:1-12` sets `KIND='plants'`, `ANIMAL='sea_urchin'`, `COUNT=1`, `RESIDENTS=[]` and `ROCKS`. It has no species list or animal flag.

`generate.py` builds the animals from `KIND` alone:

- The Player **is** the urchin: mesh `sea_urchin.iff`, visibility 1160 (`:209-218`).
- The goby body and fins use visibility 1161 (`:243-247`).
- 8 tube feet (`:248-256`) and 8 spine pivots (`:257-265`) use visibility 1160.
- 12 seahorse bodies and fins come from `seahorse.placements()` (`:269-283`), and the 6 posts and branches from `seahorse.POSTS` (`:284-287`).
- 3 grazing rocks use visibility 1161 (`:316-319`).

Water type picks the resident at runtime, not in the generator: `pg-salt dup 1160 tk! not 1161 tk!` (`:503`), and the Player tick is `pg-salt if tk-urchin-player-tick else … gb-player-tick` (`:498`). The seahorse count is a runtime catalog field (8), not a build count.

The other tanks select variations with environment and config switches (`LIONFISH_FEEDING` `:38`, `BETTA_FINS` `:40`, `PLANTED_TANK_DETAIL` `:80`, `C.WIDE_CAMERA` `:368`). A `C.ANIMALS` flag follows that pattern.

### Q2: what a text strip would have to do, and what breaks

Indices are positional, in `.lev` OBJ order (`generate.py:382-383`). The current map has 81 actors: animals at 10-57 and 66-68, plant chunks at 69-76, `LookClose` at 80 and `cs_close` at 81. Removing the animals renumbers the chunks to 18-25, `LookClose` to 29 and `cs_close` to 30. Indices 1-9 (Director 4, Player 9, `cs_wide` 7) do not move.

Both scripts bake indices as literals in `aquarium_plants.lev` (lines 276 and 910): `tk-cam-close 81`, `tk-look-close 80`, `0 69 plant-register` and so on, plus every foot, spine, seahorse and goby index in the Director tick. `plant-register` stores whatever index it gets, and `plant-step` silently skips any index out of range (`scripting_zforth.cc:1323-1335`). A stale index therefore draws no plants and reports no error. Unrenumbered urchin calls would also write poses into the actors that now sit at 12-27: the tank shell, the floor and the plant chunks 18-25.

The `settings.rprp` owner resolves by name through `actor-map.json` (`build-object-properties.py:90`). The Director stays 4, so the catalog survives either way.

Animal references by script:

| Script | Effect if the animals are left out of the build |
|---|---|
| `urchin_motion.fth`, `urchin_spines.fth` | Wrong actor writes |
| `goby_controller.fth` (Director and Player) | Writes to indices 10/11 |
| `seahorse_behaviour.fth` and generated `seahorse_posts.fth` | Reads fields 8/9 every frame |
| `screensaver_player.fth` | Drives the urchin crawl, which is pointless without the urchin |
| `plants_controller.fth` | `tk-camera-tick` reads only the Player, so it is harmless |

### Q3: what the engine requires of a level

**A Player is required.** Without one, the load prints only a warning (`level.cc:814-815`). But `Level::reset()` then runs `assert(ValidPtr(main_char))` and `ObjectIsInWhichRoom(GetObjectIndex(main_char))` (`level.cc:1592-1596`) to choose the active room. So keep an invisible Player, like the non-plant tanks' hull with visibility 0 (`generate.py:212,215,218`).

No camera follows the Player in the `.lev`. `Camera` has an empty `Object To Follow`. `cs_wide` follows `LookAt`, and `cs_close` follows `LookClose`. Only the Forth `tk-camera-tick` moves `LookClose` and `cs_close` to the Player and picks the camera shot from mailbox 625 (`plants_controller.fth:33-40`). The A-tap in Forth is already compiled out in runtime-detail builds (`generate.py:492`). The native tap is `game.cc:677`.

Assets:

- `front_collider.iff`, the tank shell, `floor` and `stand` are generic tank geometry. Keep them.
- The grazing rocks, `rainbow_goby_*`, `urchin_*`, `sea_urchin` and `seahorse_*` simply are not generated.
- `navigation_target.iff` is a stale tracked file that no `.lev`, `asset.inc` or `.iff.txt` references. The builder symlinks every `*.iff` (`build-aquarium-screensaver-levels.py:79-83`), but only referenced assets are embedded, so leftovers are harmless.

### Q4: rooms and memory

- **`ROOM`: keep 24 MB.** The 24 MB is for the expanded runtime foliage (`aquarium_plants-standalone.iff.txt:2,7`), not for the animals.
- **`PERM`: can shrink.** `PERM 6000000` grew for the seahorse DFRM rigs (comment at `:3-4`), so the variant can return to about 1 MB. Measure it in Phase 5.
- **Texture pages.** The leaf atlas lives on `Room0` (256²) and is unchanged. Every `PERM` texture is an animal or rock texture (`textile.flags`, 1024² for five textures). Without them `PERM` becomes an empty stub page, like jellyfish's 4×16 `Perm.tga`, which is a normal state. No 1024² permanent slot is needed.

### Q5: the Seahorses (8) and Greeting (9) fields

The only runtime readers are the generated seahorse words `sh-count` and `sh-greeting` (`seahorse.py:883-884`), called from `sh-settings`. The tooling that also reads them is `plant_settings_catalog.py:17` and `build-planted-seahorse-variants.py`. `planted::enter()` reads only fields 1-7 (S3).

**Remove them** from the variant: drop the sheet at `settings.oas:15-17` and the two bindings. `build-object-properties.py:32-33` skips any unbound field, so dropping the bindings alone is enough. Otherwise the hold‑A panel shows a sheet that does nothing. Give `Hold seconds` a new id (10) rather than reusing 8 or 9, so tools keyed to 8 = Seahorses cannot mistake it.

## Limits

I did not check whether a `Model Type None` Player (with no mesh) passes levcomp and physics. The hull mesh is the tested path, so the recommendation uses it.
