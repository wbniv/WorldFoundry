# Plan — Q*bert Red Ball Phase B (multi-ball, spawning, timing, arc)

**Status:** Not started
**Phase A baseline:** commit `2752d41` — one self-respawning ball, mb 462..466, strict alternation, no Z arc.

## Context

Phase A landed a single Red Ball that bounces in a self-respawning loop. It proved the per-actor script + global mailbox + FALL_DEATH pipeline works, but it isn't arcade-faithful:

1. **Only one ball at a time.** Arcade Q*bert runs 2–3 balls simultaneously on a per-round spawn cadence.
2. **No director involvement.** Per user direction, the director should *enable* enemies (decide when to wake one) while each enemy owns its own movement script. Phase A's "ball loops itself forever" is the wrong shape.
3. **Strict left-right alternation.** Arcade picks the next hop direction randomly per step.
4. **No parabolic Z arc.** Player has a smoothstep + arc lerp; ball teleports flat between cubes.
5. **No initial-delay / per-round timing curve.** First ball appears immediately on the first tick, including during the intro pan.

Phase B fixes all five inside a single edit pass to `blender_create_qbert.py` (no engine changes).

## Architecture

- **3 red-ball actors** pre-created in the .blend (`redball_0/1/2`), all running the same generated wf_Script (parameterised by ball-index `K ∈ {0,1,2}`).
- **Director gates activation.** A new spawn-timing block in the director script (gated on `INTRO_DONE = mb 418 == 1`) decrements a spawn timer; on expiry it picks the lowest-index idle ball and writes its initial state (PHASE=1, ROW=1, COL=0|1 via LFSR, COOLDOWN=18, START_Z=apex, END_Z=row-1, plus initial X/Y/Z) via `write-actor-mailbox`. Director never reads a ball back — it tracks ball-active state in its own globals (`RB_ACTIVE[K]`), which each ball clears when it retires.
- **Each ball owns**: per-tick countdown, mid-hop XYZ animation (cube-space row/col lerp + smoothstep + parabolic Z bonus, mirroring the player's pattern), landing decisions (random next direction via shared LFSR, off-pyramid retire, contact check vs. player ROW/COL latches FALL_DEATH).
- **One shared 16-bit LFSR** at mb 511 drives both spawn-cube selection (col 0|1) and per-hop direction. Cross-ball correlation is acceptable for a coin-flip stream.

## Mailbox layout

Per ball K, base `462 + 8*K`:

| off | name | use |
|-----|------|-----|
| 0 | `RB_ROW` | current pyramid row (0=apex, 6=bottom) |
| 1 | `RB_COL` | current pyramid col |
| 2 | `RB_COOLDOWN` | ticks remaining in current hop, 18→0 |
| 3 | `RB_PHASE` | 0 = idle (off-screen at Z=-30), 1 = hopping |
| 4 | `RB_START_Z` | Z at start of current hop |
| 5 | `RB_END_Z` | Z at end of current hop |
| 6 | `RB_FROM_ROW` | row before current hop (for row-space lerp) |
| 7 | `RB_FROM_COL` | col before current hop |

3 balls × 8 = 24 cells: **462..485**.

Director-owned globals:

| mb | name | use |
|----|------|-----|
| 511 | `RB_LFSR` | 16-bit Galois LFSR state (seed `0xACE1`) |
| 512 | `RB_SPAWN_TIMER` | ticks until next spawn attempt |
| 513 | `RB_DIRECTOR_INIT` | one-shot init latch (separate from existing `LEVEL_INITIALIZED` to keep the seed write outside the player's restart path) |
| 514..516 | `RB_ACTIVE[K]` | director's mirror of each ball's PHASE (so director can read without `read-actor-mailbox` which doesn't exist) |
| 517 | `RB_SPAWN_CLAIMED` | 1-tick scratch — prevents two activations in one tick |

`RB_PATTERN` from Phase A is **dropped** (replaced by LFSR).

## Per-ball script (generated by `redball_script(K)`)

```forth
\\ wf redball K
\\ Phase 0: idle — director will wake.
{MB_PHASE} read-mailbox 0 = if exit then

\\ Phase 1: hopping. Decrement cooldown.
{MB_COOLDOWN} read-mailbox 1 - dup {MB_COOLDOWN} write-mailbox

\\ Compute t = (HOP_TICKS - cd) / (HOP_TICKS-1)  ∈ [1/17 .. 1]
\\ then smoothstep: t' = t*t*(3 - 2*t)
\\ Player's idiom (blender_create_qbert.py ~line 596):
\\   "dup dup * swap 2.0 * 3.0 swap - *"

\\ Row-space lerp → world XY:
\\   row_now = FROM_ROW + t'*(ROW - FROM_ROW)
\\   col_now = FROM_COL + t'*(COL - FROM_COL)
\\   x = X_MUL * (col_now - row_now*0.5)
\\   y = Y_MUL * (6 - row_now)
\\ Write 3009/3010.

\\ Z lerp + arc:
\\   z_linear = START_Z + t'*(END_Z - START_Z)
\\   z_arc    = z_linear + 4*t*(1-t)*2.0          ← player's parabola
\\ Write 3011.

\\ When cd <= 0: landing tick.
{MB_COOLDOWN} read-mailbox 0 <= if
  \\ contact check
  {MB_ROW} read-mailbox 400 read-mailbox = if
    {MB_COL} read-mailbox 401 read-mailbox = if
      1 414 write-mailbox
    then then

  \\ off-pyramid retire
  {MB_ROW} read-mailbox 6 > if
    0 {MB_PHASE} write-mailbox
    0 {MB_ACTIVE_FOR_K} write-mailbox
    -30 3011 write-mailbox
    exit
  then

  \\ pick next direction via LFSR (inline; one bit consumed)
  <rb-rand-inline>                            ( bit )

  \\ stash from-row/col; advance row/col
  {MB_ROW} read-mailbox dup {MB_FROM_ROW} write-mailbox 1 + {MB_ROW} write-mailbox
  {MB_COL} read-mailbox {MB_FROM_COL} write-mailbox
  0 <> if {MB_COL} read-mailbox 1 + {MB_COL} write-mailbox then

  \\ stash START_Z (current Z) and END_Z (for new row)
  3011 read-mailbox {MB_START_Z} write-mailbox
  {Z_BASE} {MB_ROW} read-mailbox {Z_MUL} * - {MB_END_Z} write-mailbox
  18 {MB_COOLDOWN} write-mailbox
then
```

**Contact check** also fires every frame (not just landing) — preserve Phase A behaviour.

## LFSR (inline; no PRNG in zForth)

zForth has `&`, `|`, `xor`, `+`, `<>`. No `/`-as-integer, no `<<`. Use `dup +` for left-shift-by-1; mask `0xFFFF` to keep 16-bit period. Fibonacci taps 16/14/13/11 (`0xB400`-class polynomial), bits extracted by `& 0 <> 1 and`:

```forth
511 read-mailbox                              ( s )
dup 0x8000 & 0 <> 1 and                       ( s b15 )
over 0x2000 & 0 <> 1 and xor
over 0x1000 & 0 <> 1 and xor
over 0x0400 & 0 <> 1 and xor                  ( s fb )
swap dup + 0xFFFF & or                        ( s' )
dup 511 write-mailbox
1 &                                            ( bit )
```

## Director additions

**Inside the existing `LEVEL_INITIALIZED` (`421 read-mailbox 0 = if …`) one-shot block:**
```forth
0xACE1 511 write-mailbox     \ seed LFSR
120 512 write-mailbox        \ first-ball delay ~2 s after INTRO_DONE
0 514 write-mailbox 0 515 write-mailbox 0 516 write-mailbox  \ all idle
```

**After intro state machine, before camshot routing (gated on `418 read-mailbox 1 =`):**
```forth
418 read-mailbox 1 = if
  512 read-mailbox dup 0 > if 1 - 512 write-mailbox
  else drop
    <rb-rand-inline>                          ( col_bit )   \ 0 or 1
    0 517 write-mailbox                       \ claimed = 0

    \ ball 0 activation (repeated unrolled for K=1, K=2):
    517 read-mailbox 0 = 514 read-mailbox 0 = and if
      <activate-K=0 col_bit-on-stack>
      1 517 write-mailbox
    then
    \ ball 1: same gate on 515; K=1
    \ ball 2: same gate on 516; K=2

    drop                                       \ drop col_bit
    \ rearm: interval = max(60, 300 - 12*ROUND_NUMBER)
    425 read-mailbox 12 * 300 swap - dup 60 < if drop 60 then 512 write-mailbox
  then
then
```

**`<activate K=k>` macro** (val/mb/actor stack for `write-actor-mailbox`):
```forth
\ col_bit on stack as `col` (0 or 1)
dup     MB_COL_K      REDBALL_ACTOR_BASE k + write-actor-mailbox
1       MB_ROW_K      REDBALL_ACTOR_BASE k + write-actor-mailbox
0       MB_FROM_ROW_K REDBALL_ACTOR_BASE k + write-actor-mailbox
0       MB_FROM_COL_K REDBALL_ACTOR_BASE k + write-actor-mailbox
18      MB_COOLDOWN_K REDBALL_ACTOR_BASE k + write-actor-mailbox
14.5    MB_START_Z_K  REDBALL_ACTOR_BASE k + write-actor-mailbox   \ row 0 Z
12.5    MB_END_Z_K    REDBALL_ACTOR_BASE k + write-actor-mailbox   \ row 1 Z
1       MB_PHASE_K    REDBALL_ACTOR_BASE k + write-actor-mailbox
1       (514+k)       write-mailbox                                 \ director's own mirror
```

Spawn-interval curve: `max(60, 300 - 12 * ROUND_NUMBER)` ticks. At ROUND 0 → 5 s; at ROUND 15 → 2 s; clamped at 1 s.

## zForth gotchas to verify in implementation

1. `/` is float — never use inside the LFSR. `dup +` is the only integer shift available.
2. Cell width may be wider than 16 bits — `0xFFFF &` after each LFSR step is load-bearing.
3. No early-exit `loop` mechanism — director activation cascade uses an unrolled `claimed` flag.
4. `write-actor-mailbox` stack order is `( val mailbox actor_idx -- )` — matches the cube fan-out pattern at the existing director script (~line 1040).
5. Bake mailbox indices as Python f-string literals into each generated script — no runtime arithmetic on mb numbers.
